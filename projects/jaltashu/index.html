담당 역할

인프라

팀이 개발한 서비스와 데이터 모듈을 두 EC2에 배치하고, Docker 실행 환경과 연결, 배포 및 복구 검증을 담당했습니다.

AWS EC2, ECR, S3, Docker, Jenkins, Nginx, MySQL, Redis

Backend, Frontend, Collector, Kafka/Spark 처리 로직과 AI 모델은 각 팀 담당자가 개발했습니다. 저는 모듈의 실행 환경과 서비스 간 연결, 접근 권한을 구성했습니다.

핵심 사례

승인 취소와 후보 정리자격증명 수정과 재시작 결과백업과 격리 복원 결과

승인 취소 뒤 남은 배포 후보 정리

수동 승인 대기 중 배포를 취소했는데, 비활성 슬롯에 후보 컨테이너와 상태 파일이 남았습니다.

직접 한 작업

Jenkins 후처리에 후보 정리를 연결하고 SSH 계정을 수정했습니다. 요청 SHA 비교와 활성 슬롯 삭제 거부 조건으로 정리 대상을 제한했습니다.

확인한 결과

취소 후 후보와 상태 파일 제거, 활성 슬롯 유지와 서비스 정상 응답을 확인했습니다.

세부 구현과 확인 내용

Jenkins 후처리에 후보 정리를 연결했습니다. 요청 SHA와 후보 SHA를 비교하고, 활성 슬롯은 삭제를 거부하도록 보호 조건을 추가했습니다. 정리에 실패하던 후처리 SSH 계정도 배포 계정과 일치하도록 수정했습니다.

같은 서버의 Blue/Green 슬롯이며 운영 DB를 공유합니다. 이미지 롤백과 DB 변경 복구는 별개입니다.

재시작 후 사라진 Jenkins 자격증명 복구

Controller 재시작 뒤 Job과 빌드 기록은 남았지만, GitLab 자격증명이 사라져 저장소 인증이 실패했습니다.

직접 한 작업

UI 등록 자격증명이 JCasC에 선언되지 않은 상태를 수정했습니다. 자격증명 정의는 JCasC에, 실제 값은 Docker Secret에 분리했습니다.

확인한 결과

실제 서버 재시작 후 자격증명, Job과 Agent 유지 및 Polling 자동 빌드 성공을 확인했습니다.

세부 구현과 확인 내용

UI 등록 자격증명이 JCasC 선언에 없는 상태를 구분하고, 실제 값은 Docker Secret으로 공급하며 자격증명 정의는 JCasC에 선언하도록 수정했습니다. 필수 값 누락 시 Jenkins 시작도 차단했습니다.

S3 백업을 다시 내려받아 격리 복원

생성된 백업을 검사하고, S3에서 다시 받아 SQL을 복원할 수 있는지 확인했습니다.

직접 한 작업

백업 생성과 gzip 검사, checksum 및 S3 보관을 연결했습니다. 다시 내려받은 파일을 격리 MySQL에 SQL import했습니다.

확인한 결과

checksum 일치와 SQL import 후 두 스키마의 존재를 확인했습니다.

세부 구현과 확인 내용

중복 실행 lock, 임시 파일 생성과 gzip 검사, 완료 후 rename과 checksum을 구성했습니다. S3 보관을 연결하고 외부 네트워크와 영구 볼륨이 없는 격리 MySQL에서 SQL import를 수행했습니다.

확인한 범위는 파일 일치, SQL import와 스키마 복원입니다.
