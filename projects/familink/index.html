담당 역할

백엔드 및 인프라

그룹과 피드 API, DB 규칙과 S3 직접 업로드 API를 구현하고 AWS 실행 환경과 Jenkins 배포 절차를 구성했습니다.

Java, Spring Boot, JPA, PostgreSQL, Flyway, AWS, Docker, Jenkins

핵심 사례

권한 검사와 DB 제약S3 구현과 서명 변경배포와 이미지 복구 절차

그룹 권한은 API와 DB에서 함께 검사

여러 가족 그룹에 참여하더라도 그룹별 역할과 접근 권한이 구분되어야 했습니다.

직접 한 작업

그룹 멤버십에 역할과 탈퇴 상태를 저장하고 API 접근 권한을 검사했습니다. PostgreSQL 조건부 UNIQUE 인덱스로 그룹별 활성 관리자를 최대 1명으로 제한했습니다.

구현한 내용

권한 검사와 DB 저장 제약을 함께 적용하고 Flyway로 스키마를 관리했습니다.

세부 구현과 확인 내용

계정과 그룹 멤버십을 분리해 역할, 관리자 여부와 탈퇴 상태를 저장했습니다. 피드, 댓글과 반응 API에서 활성 구성원과 작성자 권한을 검사하고, PostgreSQL 조건부 UNIQUE 인덱스로 그룹별 활성 관리자를 최대 1명으로 제한했습니다.

활성 관리자 최대 1명을 제한합니다. 반드시 1명 존재하는 조건은 아닙니다.

모바일 업로드 실패에서 서명 조건까지

URL 발급 API와 수동 curl PUT은 성공했지만, 모바일 앱의 업로드는 실패했습니다.

직접 한 작업

Presigned PUT URL API와 실제 S3 연결, HeadObject 검증 및 비공개 GET URL을 구현했습니다. 모바일 Blob 전송 기준을 맞추고 Content-Length를 서명 조건에서 제외했습니다.

확인한 결과

추가 검증(2026-10-19): 로컬 서명 테스트에서 Provider 회귀 테스트 3건 통과.

세부 구현과 확인 내용

기존 계약에 따라 Presigned PUT URL 발급 API를 구현하고, 실제 S3 연동과 HeadObject 객체 검증, 비공개 조회용 GET URL을 연결했습니다. 모바일에서는 실제 Blob 크기로 URL을 요청하고 같은 Blob을 전송하도록 보완했습니다. 백엔드는 Content-Type을 유지하고 Content-Length를 서명 조건과 반환 헤더에서 제외했습니다.

추가 검증의 범위는 AWS SDK의 로컬 서명 헤더입니다.

배포할 이미지와 복구할 이미지를 구분

배포할 버전과 실패 시 다시 실행할 이전 이미지를 구분할 수 있어야 했습니다.

직접 한 작업

Jenkins에서 Docker 이미지를 빌드해 Commit SHA 태그로 ECR에 저장하고, SSM으로 운영 EC2 배포를 연결했습니다.

구현한 내용

Health Check 실패 시 기록해 둔 이전 이미지로 재기동하는 절차를 구현했습니다.

세부 구현과 확인 내용

팀 프로젝트 기간에 EC2, RDS, S3 환경을 구성했습니다. Jenkins에서 Docker 이미지를 빌드해 Commit SHA 태그로 ECR에 업로드하고, SSM Run Command로 운영 EC2의 배포 스크립트를 실행하도록 연결했습니다.

이미지 복구와 DB 스키마 복구는 별개입니다.
